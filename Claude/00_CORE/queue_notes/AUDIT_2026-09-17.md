## ⭐⭐⭐ THE ONE THAT MATTERED MOST: the game booted in the wrong mode

`initialBehaviour()` returned `TRANSLATE`. `CLAUDE.md`, this file's neighbours, and
`scene.ts`'s own call-site comment all said **`ROTATE`** — the owner's *"Default start: rotation
mode"* of 2026-09-16.

⛔⛔ **AND `git log -S'return "ROTATE"'` FINDS NO COMMIT THAT EVER DID.** Nothing regressed. The
decision was recorded in every document and **never reached the code**, and
`tests/mode_toggle.test.ts` asserted the value the function *returned* rather than the decision
the owner *made* — so the suite defended the defect for a day.

⭐⭐ `METHOD` gains: **a vector written from the code it tests cannot contradict that code.**
It is the `A7` shape one layer lower — a correct decision, recorded everywhere except in the
one place that runs. ✅ Re-confirmed by the owner 2026-09-17 and fixed.

⚠ A second vector in the same file broke on the fix, because it had encoded the boot value a
second time (*one toggle from boot must give `ROTATE`*). It asserts a **flip** now, not a
literal: *a vector states the property it names; a literal borrowed from elsewhere is a
hidden second assertion about that elsewhere.*

## ⛔⛔⛔ THE LATENT ONE `3D2` WOULD HAVE ARMED — a COUNT standing in for a QUESTION

Three guards read **`stack.length === 1`**, meant *"is this body aligned?"*, and fell through to
**FREE ROTATION** for every other count: the one-finger twist, the second finger's roll, and the
`FOLLOW` retarget. A fourth read `constraints.length > 0` and counted a **MATE** as an alignment.

⚠⚠ Unreachable today only because `singleAlignment` caps the stack at one — **and a mate is the
second entry**. ⛔ The first seated body to be dragged would have rotated freely and broken its
mate and its alignment together, with every vector green. `QUEUE.md` already carried the
warning in prose; it is now a structure instead.

✅ **`rotationChannel(stack)` replaces all three**, with three verdicts — `FREE`, `TWIST`,
`REFUSED` — and `hasAlignment(stack)` replaces the fourth.
⭐⭐ **The third verdict is the point.** What a drag should do to a seated body is `3D2`/`3D3`'s
decision and has *not been made*; the honest answer is a refusal that says so on the HUD.
⛔ `LESSONS_CARRIED` §6 — *a degenerate input returns null, never a default* — and a length test
had silently chosen the most destructive default available.
⚠ The refusal **returns** rather than falling through. Setting a verdict and carrying on would
have been worse than the defect: the HUD would report the refusal while the mate broke.

## ⭐⭐ THE OWNER'S DECISION: frozen and the assembly tree

`frozen` was enforced at `setWorldPlacement` and `pushObjectConstraint`, and the header claimed
that made it hold *"for rules that do not exist yet"*. ⛔ `local` has **five** writers, not two:
`attach`, `reroot` and `detach` were uncovered.

⚠ Measured: `attach(w, "plate", "part")` then moving the part put the plate at `[5, −1, 0]` —
**with no rule ever writing the plate's placement**. A child's placement is relative.

✅ **The owner's rule, 2026-09-17: PARENT YES, CHILD NEVER.** `attach` refuses a frozen child;
`reroot` refuses any re-rooting that would make a frozen body a child; `detach` is allowed,
because it writes the body's own current world placement and moves nothing.
⭐ It is the same distinction `frozen` already draws for alignments — *a frozen body may still
be a PIONEER* — and for the same reason: a base plate is the thing others mount **onto**.

## ⚠ FRAGILITIES CLOSED, IN ONE LINE EACH

* **One snap slot for the whole scene** → `input/align_snap.ts`, one per body, 13 vectors. A
  second alignment mid-flight used to abandon the first body **mid-arc**, keeping its
  constraint, its marker and its outline while its face was not on the target.
* **The link baseline was a `local` orientation** and the cascade compared it against a
  **world** one. Identical while the tree is flat; the first parented Pioneer would have read
  as *turned* by its parent's whole orientation on frame one.
* **`AlignmentLinks.link` accepted self-links and cycles** — the header said the state was
  *"unrepresentable"* and this module's own suite built `a→b→a` through the public API to test
  the detector for it. `link` refuses now; the walk's `seen` set stays as depth.
* **`orbitTopRadiusM = 0` was vectored as legal and made every press throw** in
  `requireGestureFrame`. Two components, two opposite invariants, each with a comment. The
  validator now refuses a non-positive radius, and a new sweep measures that the orbit surface
  never reaches a pole.
* **A re-pressed pointer id left its old grip in `held`**, ticked every frame — defect 40 and
  `A13`'s shape again.
* **`constrainedRollAngle` tested `c === 0`**, an exact float comparison, so the guard could
  essentially never fire. Now the 1e-9 its own sibling uses.
* **`solve` contradicted itself in two results**: an overflow refusal reported two constraints
  `applied` beside an IDENTITY rotation, and a degenerate entry 1 reported `rejected: false,
  freeDof: 1` — *two DOF consumed, the face is on its target* — when nothing had happened.
* **The render loop drew the scene before the slerp and the cascade wrote the model**, so an
  animating body lagged its own model by a frame. The slerp's comment claimed it ran *"before
  anything reads an orientation"* — true of the markers, false of the loop that draws.
* **The HUD was one event behind the loop's own verdicts.** The instrument built to tell a
  stale marker from a broken rule was itself stale.
* **A drag on the frozen plate did nothing and said nothing.**
* **`randomQuat` was outside `vec.ts`'s canonicalisation contract.**

## ⛔⛔ WHAT IS **NOT** FIXED, AND WHY

⭐ Each of these is a real finding that a code change would have answered dishonestly.

1. **Thresholds in "millimetres" are CSS-reference millimetres, not physical ones.**
   `core/units.ts` converts at 96 px/inch because browsers expose no physical DPI. ⚠ On the
   reference tablet (10.3", 1920×1200, DPR 1.5 ≈ 147 CSS px/in) the 3.5 mm deadband is about
   **2.3 physical mm**, and every HUD readout in mm is off by the same ratio.
   ⛔⛔ **`CLAUDE.md` rule 3 says *millimetres on the physical screen*, and that is not what is
   being computed.** Numbers tuned on one device are self-consistent and will NOT transfer to a
   device of a different pixel density. ⚠ A fix needs a calibration the owner performs by hand
   (a known length held against the glass), which is an `IN5` device task, not an edit.
2. **The roll's direction reverses at full rate as the camera crosses square to the alignment
   axis.** The magnitude does not depend on how square the axis is — only the sign does. ⭐
   Making it fade with `|c|` would remove the discontinuity **and change the feel everywhere
   else**, and *"the object must follow the finger"* at full rate was deliberate. ⚠ A hand
   decides this; the behaviour is now pinned by a vector so a change to it is visible.
3. **The `4L` capture radius is centre-to-centre and cannot be right for the base plate.**
   ⛔ Measured: at boot the plate's centre is **312.4 mm** from `objectA` and `objectB`, inside
   the 320 mm radius — so `scene.ts`'s claim that *"at 5L nothing is in range"* was false, and
   dragging either part at boot raises the white pair on the plate at once. ⚠ Nudging the radius
   trades one wrong answer for another: the plate is `6L × 9L`, so a part resting ON it near an
   edge is further from its centre than one hovering high above the middle. ⭐ The fix is the
   face-distance rule the owner has already named (*"later we will use distances between
   faces"*), which `3D2` owes. The comment is corrected and a vector states the number.
4. **`nearestCapture`'s tie rule is not hysteresis.** It compares with `===`, so it holds the
   incumbent only for a bit-for-bit tie; a challenger `1e-13` nearer takes the target. Real
   hysteresis needs a margin in millimetres that no hand has judged, and *a guessed number has
   been wrong every single time here*. The overclaiming comment is corrected.
5. **`rollOrder` has no reader in `src/`.** Left in place with a note: it is what makes a mate
   **fastened** rather than **revolute**, and `3D2` is the row that gives it one.
